# Compare alternatives to one action

Lock the common action first: source/attachment, gameplay footprint, startup, pulses, recovery, interruption and lifetime. Reuse gameplay data; candidates supply presentation only. Author profiles and prefabs rather than copies of combat logic.

Differentiate silhouette, negative space, layer relationships, real surface flow and simulated motion. A shared family palette still needs deliberate hue/value separation. Do not replace the effect with a completed illustration on a bouncing or scaled card. Use effect textures as flow/foam/dissolve masks or actual animation frames, with native particle, mesh, trail and material techniques appropriate to the request.

Register stable numbered names in the browser. Match the floor, camera, backdrop and scale across candidates. Review onset, a steady main phase, pulse response, breakup, interruption and cleanup. At steady overall scale, interior water/contour flow and particles must still evolve. Native motion captures supplement the playable browser; peak stills do not establish motion quality.

Preserve live content until the user selects when requested. Technical verification or agent preference does not imply artistic acceptance.

Read the [four water references and user critique](water-direction.md). The first set was rejected for shape, spacing, color and motion problems. The second set was rejected as bouncing PNGs. No candidate is selected or approved.

The current ten live under `Assets/_Project/VFX/RisingWaterVariants` with the same stable `fountain.<key>` registrations.
