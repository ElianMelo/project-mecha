# Architecture decisions

User decisions recorded 2026-10-14; apply these to future features.

1. Use this order: Unity built-in systems/components, official Unity packages, established widely used maintained packages, and custom solutions only as a last resort. Inspect installed capabilities first, check project compatibility, and record the missing capability before introducing a custom replacement. Combat VFX use Particle Systems; cameras use Cinemachine; animation uses Animator; room walls use colliders. Custom scripts connect these systems rather than reimplementing them.
2. ScriptableObjects own authored configuration: movement, input timing, attack/skill definitions, presentation clips, enemy behavior, camera/room bounds, toon lighting and particle profiles. Components reference configuration and retain per-instance state. Runtime code does not write back to configuration assets.
3. Keep PlayerInputs, PlayerMovement and PlayerAttack separate. Animation and effects have separate presentation components. Keep files focused, expose meaningful interfaces, and reuse systems across player/enemy where practical.
4. Record decisions and implementation/validation notes. Preserve existing networking authority and asset GUIDs when moving assets.
5. No automated tests without an explicit request. Validate through compilation, code review and manual Play Mode observations; restore editor state afterward.
6. Use Unity's official local MCP connection: Unity CLI (`unity mcp`) plus `com.unity.pipeline`. Discover the connected Editor's available commands and use its Unity APIs for asset and package changes. The former third-party MCP package and generated skills were removed on 2026-10-14. See [setup and validation](UnityMcpSetup.md).

The 2026-10-14 visual/camera/character pass follows these decisions. Existing unrelated networking and UI configuration can migrate when those systems are next changed.

Implementation patterns to repeat: ICombatTarget defines damage reception; IHitFeedback defines reusable impact presentation; CharacterAnimator owns animation presentation; ParticleBurstEmitter uses Unity ParticleSystem with authored profiles. RoomCameraRig supplies a tracking point and damping to Cinemachine Position Composer, while Confiner 2D and separate 3D wall colliders own framing and physical limits. Native Unity asset settings remain editable through their usual inspectors, referenced/configured from the profiles.

EnemyStateMachine and small IEnemyState implementations own enemy decisions; EnemyController owns authoritative combat and health, EnemyMotor owns physics, EnemyPlatformNavigator owns platform routing, and EnemyCrowdAvoidance owns local spacing. EnemyStateSettings, EnemyTraversalSettings and EnemyCrowdSettings author their tuning. This side-view platform arena uses a small graph of actual collider surfaces and Unity physics rather than a ground-plane NavMesh. OneWayPlatform exposes its active surfaces so navigation and collision use the same platforms. Server authority owns enemy movement, damage, and accepted dash protection; grounded presentation and enemy state are replicated to clients.

ArenaLayoutSettings owns the authored platform/spawn layout and room extent; MechaArenaSetup applies it through Unity APIs. Dash is an immediate escape from attack startup, active frames and recovery, clearing queued combo/skill inputs and future hit pulses. Starting another attack ends the dash and its protection; cancelled skills retain their spent cost/cooldown. Crowd spacing targets 20–40% overlap of the combined collider radii as nearby density increases. It remains soft steering: airborne routing and knockback can temporarily exceed that target.

See [gameplay refinement process and observations](GameplayRefinements.md) for the 2026-10-14 adjustments and their validation limits.

PlayerAwareness owns the three player-centered ranges through PlayerAwarenessSettings. Hard-range detection enters Alert immediately; soft and large ranges select Suspicious and Wander, with randomized dwell/retention times and hysteresis in EnemyStateSettings. State instances keep per-enemy runtime memory; configuration assets remain shared read-only data. Wander patrols a local spawn-home area and reuses the same platform navigation as pursuit. Finite encounter spawning tracks a cumulative quota and finishes once placed; defeated enemies do not replenish that quota.

PredictionState adds an interception branch from Alert. EnemyPredictionPlanner chooses another reachable platform using current player movement and EnemyPredictionSettings. It retains that route while waiting on another elevation; immediate melee proximity, the player reaching its platform, damage or expiry return to direct combat. This is a deliberate exception to unconditional hard-range pursuit while vertically separated. Planning, state lifetime, motor movement and combat remain separate, server-controlled responsibilities. The state identifier is replicated through the existing enemy state SyncVar.

Camera Y uses a restrained, damped airborne follow rather than a hard jump lock. Each takeoff anchors to the current visible camera height and supporting surface height, including when interrupting a landing ease. Current tuning follows 18% of vertical displacement, caps the airborne offset at 0.55 units and smooths it over 0.35 s with a 1.2 units/s speed limit. Landing begins an immediate 0.96 s ease to the supporting surface's framing height, with zero starting and ending slope. RoomCameraSettings owns these values and the native AnimationCurve. RoomCameraRig supplies a virtual tracking height to Cinemachine, retaining native horizontal composition and confinement. The current arena has flat collider tops; sloped or moving surfaces need a dedicated support-height policy when introduced.

Physical collision contact publishes the player's support immediately, in addition to the existing ground probe. Camera contact targets use collider tops rather than waiting for the body to settle. RoomCameraSettings.groundedRiseByElevation maps support elevation to camera rise above the floor's framing height. The floor and low deck share the same camera Y; higher tiers progressively raise the feet in the viewport. Current grounded feet heights are 10%, about 36%, 40% and 48% on floor, low, upper and summit tiers. This supersedes the earlier 10/30/40 step policy. Native room confinement can take precedence at room edges. Horizontal confiner bounds match the floor tile extent exactly, with no extra outward padding; invisible 3D wall colliders remain outside that extent.

RoomCameraZoom observes the locally controlled player's actual skill/dash state; combat and movement do not own camera effects. RoomCameraZoomSettings owns the zoom amounts and separate entry/return smoothing. It adjusts the Cinemachine lens before the rig computes its tracking point, and invalidates the native Confiner lens cache when size changes. Absolute offsets blend across action cancellation rather than accumulating. Ground framing uses the base lens size while tracking-point compensation uses the current lens, so zoom does not itself drive vertical follow.

PresentationRenderSettings references the native URP pipeline asset and owns camera anti-aliasing, sample count and render scale. MechaRenderSetup applies the profile through Unity APIs from the repeatable camera setup. Runtime camera code does not change shared rendering assets. Current PC tuning is 4× MSAA, high-quality SMAA and full render scale. See [current camera and rendering process](SoftCameraAndRendering.md).

Existing gameplay UI uses uGUI and TextMeshPro. GameplayHudLayoutSettings owns layout, text and font sizing; MechaHudSetup edits the existing hierarchy and keeps label references. Native HorizontalLayoutGroup owns the compact skill row below HP/MP. Tutorial text is anchored top-right. Layout changes are applied through the repeatable editor setup.

ScenarioSettings owns platform art, visual dimensions and crate placements. ParallaxSceneSettings separately owns the three background images, placement, sizes, tint, copy count and rendering order. Each layer references its own ParallaxSettings; ParallaxLayer applies camera-relative motion after Cinemachine updates. Native SpriteRenderers display an opaque distant sky/city, a transparent middle skyline and transparent nearby rooftops. Neighboring image copies cover room traversal; the old cube pillars were removed. Platform art is separate from physical colliders and casts no shadows. DestructibleProp implements ICombatTarget, stores health in a server-owned SyncVar and reuses native Particle System effects. Destructible layer 10 is included in player attack queries and ignores actor movement collisions; visual depth puts crates behind the action. The scene setup invokes FishNet's editor serialization pass after batch-creating scene NetworkObjects. See [scenario implementation and validation](ScenarioAndPrediction.md).

Player/enemy body collisions are enabled; enemy/enemy collisions remain disabled for soft crowd spacing. EnemyBodyCollider registers active body colliders. PlayerEnemyCollision observes the accepted/predicted PlayerMovement.IsDashing state and ignores only that player's collider pairs during a dash, including newly enabled enemies. It restores clear pairs immediately afterward, with a maximum 0.15 s grace for overlaps. The native physics solver handles remaining penetration with a separation-speed limit from PlayerBodyCollisionSettings. This component owns neither input nor damage immunity; existing authoritative dash protection remains in PlayerHealth/PlayerMovement. Disabling it restores all ignored pairs. This pattern supports independent players without changing the global collision matrix during play.

See [current framing, body collision and parallax implementation](FramingCollisionAndParallax.md) and [the three generated-image prompts](ThreeLayerParallaxPrompts.md).

The 2026-10-15 room-flow pass uses ScriptableObject-authored procedural settings, deterministic layout data, a native-collider room builder, finite immediate enemy spawning, and a server-authoritative progression director. All enemies spawn at room start and never replenish. Clearing a room unlocks an explicit portal interaction; travel generates another compact Rising, Long, or Big room with a safe corner/center start. PlayerInputs owns interaction bindings and emits intentions to PlayerLevelTravel; the server validates portal clearance, distance, and player state. PlayerHealth owns unlimited revives at the current room checkpoint, preserving encounter progress. LevelObjectiveHud owns nearest-enemy/portal guidance through the existing uGUI system. Room descriptions are buffered for joining peers, and runtime geometry never mutates shared profile assets.

The reference-video camera supersedes the earlier capped airborne offset and landing-elevation curve: a damped vertical band follows sustained ascent/descent, with grounded support framing and a visibility safety band. Native Cinemachine composition, zoom and Confiner 2D remain responsible for their respective jobs; oversize-window confinement supports narrow rising rooms during zoom. Interception strikes preserve cooldown/range/dash rules and now use the same visible startup as ordinary melee, superseding the earlier instant-ambush tuning. See [implementation and manual validation](ProceduralLevels.md).

The subsequent 2026-10-15 co-op pass keeps FishNet for gameplay and uses the installed Unity Multiplayer Services Sessions API for public lobby discovery, membership, ready state, and Relay allocation. FishNetSessionNetworkHandler adapts the service's native Relay configuration to the existing Unity Transport; networking starts only after every lobby member is ready. PlayerInputs remains the boundary for gameplay intentions, while lobby UI and cloud membership live in separate components. Lobby settings are authored in a ScriptableObject. Host exit closes the expedition; stateful host migration is not introduced.

Server-authored enemy roles now separate home-platform guards, limited concurrent hunters, and ranged lance throwers. Guards retain their platform in patrol/suspicion; hunters retain prediction/interception. Registered network projectiles use native Rigidbody movement and server collision/damage with replicated transforms. Native crowd spacing and authored tactical settings keep enemies distributed. Rising rooms vary continuous bridges and offset ledges; their local camera lens fits the shared room width so physical side limits meet the screen edges. Parallax profile tints reduce background prominence.

The networking pass publishes remote player grounded state, derives remote motion for animation and prediction, and marks revive/travel as teleports. Player health, enemy state, projectiles, room seeds, clear state, and portal travel remain server-owned where appropriate. Two separate processes were inspected over the real Relay service, including ready-up, skill presentation, damage, revival, room transition and session exit. See [implementation, synchronization matrix, and manual validation](OnlineLobbyAndNetworkReview.md).

The encounter polish keeps jump gravity and clearance in EnemyTraversalSettings, with shorter hops for overlapping ledges and full arcs for gaps. The opening room's eight asymmetrical decks are authored in ProceduralLevelSettings; later broad rooms generate unequal merged runs and staggered heights. Lance availability is a server-owned FishNet SyncVar, while EnemyLancePresentation controls hand visibility separately from combat. Thrown lances reuse the held weapon's imported mesh and materials at the same size, launch from its hand socket, and converge onto the player's combat plane.

Combat authoring now separates AttackPiece assets from ComboDefinition sequences and a ComboLoadout. The shared catalogue resolves network piece indices to server-owned attack data; animation/effect kind remains a presentation style. ComboSequencePlayer owns each actor's cursor without mutating configuration. The dedicated ComboConfigurator scene edits private drafts and previews them through the same PlayerAttack implementation; explicit Editor save selects and persists authored sequences. PlayerLedgeAssist is separate from input/movement/combat. Native actor PhysicsMaterials avoid gravity-dependent friction stalls, while OneWayPlatform retains support until an actual departure or requested drop. All enemy strikes have windup; lancers rearm when their next windup begins. See [configuration and validation](CombatAndComboConfigurator.md).

At the user's explicit request, Sword Fire uses the supplied unity-vfx-graph skill and the official Visual Effect Graph 17.3 package. Two native GPU graphs handle flame and ember simulation; other combat effects retain Particle System. SwordFireVfxSettings owns prefab references, counts, HDR gradients and lifetime/viewing budgets; the separate emitter applies instance overrides without mutating authored data. Existing replicated attack pulses trigger cosmetics locally for owners and observers. See [assets, setup and visual validation](SwordFireVfx.md).

The 2026-10-15 pass added existing local regression fixtures for combo cursors, procedural layout and one-way-platform physics. **The current 2026-10-16 standing user preference supersedes that pass: do not create, add, modify or run automated tests without an explicit user request.** Use compilation, source review, static checks and manual runtime inspection. Separate-player builds and Relay/multi-client checks remain reserved for networking changes or evidence of a remote-only defect. See [historical test coverage and results](AutomatedTests.md).

Fixed visual graphics use authored image/Sprite assets and native Image/SpriteRenderer components rather than custom runtime shape generation. Custom shape rendering needs a concrete unmet capability after the preferred built-in/package options have been checked.

The 2026-10-16 reference-cadence decision supersedes the earlier universal dash escape: ordinary movement cannot erase combat commitment, and skills are locked through completion. Ground combos permit explicit critical (double-tap), launcher (Up), skill and magnetic-tech (X) branches at authored windows. Air attacks cancel on landing immediately, even before their first hit. Down+Z dive intent survives buffering. AttackPiece remains the authoring unit; ComboLoadout references the new branches without runtime asset mutation.

Movement is impulse-based: slow walk, a relaxed run after the basic double-tap dash, a diagonal Rocket chord, and Down-converted Mushidon with a longer slide. A short initial commitment precedes opposite-direction braking. The owner's duration is independent of later server acknowledgments, while the existing server acceptance path still gates replicated dash protection. Critical cross-through uses the body-collision exception without receiving dash damage immunity. PlayerInputs recognizes intent, PlayerMovement owns physics, and PlayerAttack owns branch legality.

EnemyMotor retains native Rigidbody collision/simulation and applies a local tempo to motion; EnemyController retains authoritative hit/stun/attack decisions. A nearby skill field slows enemies without changing global game time. Hit stop pauses the affected actor's action/motion/animation clocks. Juggle gravity is separate authored enemy behavior tuning, leaving ordinary platform traversal gravity intact. ICombatTarget exposes remaining Health so damage telemetry can report actual damage rather than overkill. Built-in physics/Animator/Particle System/Cinemachine remain the first choice; the custom code fills the concrete gap of this game's command grammar, branch rules and impulse/juggle cadence.

MechaGameplayHud keeps uGUI/TMP resource/skill displays. GameplayDiagnostics owns F3 telemetry and bounded practice controls, while SkillFocusPresentation separately observes local skill state for the native SpriteRenderer backdrop, UI Image letterbox/flash and title. Profiles own palette/layout, presentation parameters and charge/pull particle data. No custom runtime visual shape generation was added. Existing VFX Graph fire/ember assets remain in use; Unity reserialized channel metadata on four existing graphs during imports, with no new graph implementation in this pass. See [frame study, controls, tuning and validation](ReferenceCadenceAnalysis.md).

The subsequent HUD placement request groups pilot armor/energy and the skill row at the top left. GameplayHudLayoutSettings owns both anchors and offsets, and the repeatable setup preserves this placement. CharacterAnimationSettings owns run/dash reference travel speeds, playback limits and smoothing. CharacterAnimator supplies actual horizontal velocity to the native Animator PlaybackSpeed parameter, using physics velocity locally and observed motion for remote actors. Combat retains its clip-length/action-duration synchronization. Enemy playback removes local tempo from the velocity ratio before Animator.speed applies it, avoiding a second slowdown. Shared profiles remain read-only during play.

The requested compact HUD uses GameplayHudLayoutSettings.pilotHudScale = 0.5 on the native pilot panel, skill row and project identifier. Their width and height are halved without changing the overall Canvas scale or the F3 tools. Closer authored offsets remove the former empty space between groups. Skill text uses a 16-point design size (8 points after group scaling), retaining two lines without overflow. The repeatable editor setup preserves these settings.

The 2026-10-16 networking review retains FishNet 4.7.2 free and the existing Sessions/Relay transport. NetworkSimulationSettings is an editor-applied ScriptableObject profile: native TimeManager runs at 50 Hz, with two ticks of NetworkTransform/NetworkAnimator interpolation and one-tick transform sending. Unity FixedUpdate still owns physics. NetworkTransform's Rigidbody configuration owns actor replica authority and disables duplicate Rigidbody interpolation; server kinematic lance simulation remains a separate intentional case. Player animation is owner-authoritative, enemy animation is server-authoritative, and CharacterAnimator routes explicit crossfades through NetworkAnimator while observers refrain from writing animation state/speed. Native physics transforms are refreshed before authoritative melee overlap queries. Fixed actor scale is not replicated, actor facing snaps, and explicit revive/travel teleports replace distance-triggered snapping. Existing full network setup reapplies the focused synchronization setup.

User decision: do not reimplement FishNet Pro features while using free. Collider rollback/lag compensation, NetworkTransform extrapolation, selected animation parameter synchronization and network LOD remain documented upgrade slots. Current movement is owner-authoritative, not replicate/reconcile prediction; migrating it to FishNet's free tick prediction is separate work and does not require Pro. The remaining difference between displayed enemy poses and authoritative hit evaluation under latency is documented honestly in [network synchronization and Pro plan](NetworkSynchronization.md). This request explicitly authorizes the targeted network validation probe; it is development/editor-only, command-line opt-in, bounded, and exposes no remote control endpoint.

The 2026-10-16 enemy/UI polish pass makes actual horizontal Rigidbody travel determine enemy facing after navigation decisions, including retreats and indirect platform routes. Attack and hit reactions keep their intentional orientation. EnemySettings owns the movement threshold. EnemyLanceSettings reduces apex clearance from 2.8 m to 0.35 m; the existing ballistic solver remains responsible for reaching targets at different elevations. No fresh runtime console errors were reported. Lobby visuals were previewed locally without creating an online session; remote interpolation and Relay were not exercised. Play Mode was stopped and the original run-in-background value restored. No automated tests were created, modified or run.
