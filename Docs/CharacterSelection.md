# Character roster and selection

User brief, 2026-10-18: retain the current Grand Chase-like movement as **Dasher**, use the latest supplied Wing Zero model/animation set for **Zero**, preserve shared light/heavy melee combos and ranged fire, and select a character before local deployment or an online lobby.

`CharacterCatalog` contains the roster. Each `CharacterDefinition` supplies localized name/description, a real model screenshot, movement, animation, combat profile, three `CharacterSkillDefinition` slots and `CombatCapabilities`. Both characters currently allow all three shared combat channels. The capability flags reserve a configuration boundary for future character restrictions; no ranged-only mode or extra combos were introduced.

`CharacterRuntime` coordinates the selected composition. Explicit `CharacterRigBinding` sockets isolate skeleton details from movement, aiming and combat emission. Each native Animator uses its own supplied animation controller. The player prefab contains the two authored visual rigs and activates one; these are cosmetic children of the same FishNet player object. Existing hit feedback includes inactive rigs so changing character does not lose hit flashes. Character initialization reads the explicitly assigned NetworkAnimator rig instead of discovering an unrelated reticle animator.

`PlayerAttack`, `ComboSequencePlayer`, heavy attack and `PlayerSecondaryWeapon` remain shared. Skill resources, interruption and cooldown validation stay in PlayerAttack; skill assets supply presentation hooks and may replace the shared damage envelope. Zero reuses the exact existing combo loadout and non-skill AttackPiece assets. Skill action kinds remain the three existing slot identifiers (5–7) for compatibility with the shared combo/network protocol. Skill modules and their matching authored slot actions are configured together; adding a character does not require a new combat controller.

## Movement and skills

Dasher preserves the existing movement profile, double-tap dash, dash-run, chained air dash, Rocket and Mushidon. Zero runs at 7.225 units/s with stronger acceleration/air control, buffered/coyote jumps and variable jump height. RB/Shift selects an eight-direction dash from current Move input, falling back to facing. Dash speed and duration match Dasher (10.5 units/s for .20 seconds, nominal 2.1-unit traversal); diagonals are normalized and gravity is suspended during the dash. Zero does not use double-tap, Rocket or Mushidon movement chords.

Zero's editable water assets live under `Assets/_Project/VFX/ZeroWater`. A creates a growing pressure bubble 1.9 units in front, then detonates once. S generates four rising water pillars with four shared authoritative damage pulses around the player. D grants an eight-second Water Mode: 1.3× movement speed, including dash speed, and 1.4× melee cadence. Ranged fire uses the shared weapon cadence. Current casts cost 25/40/60 energy with 2/5/14-second cooldowns. These are provisional tuning values.

Modifiers are per-actor state, never changes to shared assets. Melee cadence is captured when an action starts, preventing a buff expiring halfway through an attack from moving its impact/cancel deadlines. Water Mode expires normally and clears on death. See the effect authoring note for layer/source details.

## Selection and network flow

Keyboard 1, Solo Host and Local Join open selection before connecting. The Configuration > Lobby route opens selection before the lobby browser. Direct session-create/join entry points also wait for a confirmed choice. Cancel returns to Configuration without connecting. Confirmation persists the stable character ID through GameSave JSON at `Mecha.Character.Selected`.

Each card shows a native render of its actual model with its localized name below. The shared UiNavigationScope links only the modal's active controls. Existing UiInteractionFeedback supplies persistent controller focus borders even when optional UI motion is disabled; the chosen card has a separate amber frame. Gameplay and global shortcuts are blocked while selection is visible, except Back/Menu to cancel.

The lobby publishes each pilot's character ID alongside name/readiness and shows the localized character name on their roster card. On FishNet spawn, the owner requests a catalog index once. The server validates it, locks the choice for that actor and synchronizes it to observers/late joiners. Gameplay input waits for selection acknowledgement. All peers bind the same rig/controller and combat profile. Water damage and resource costs remain server-authoritative; Water Mode uses a synchronized server-tick deadline so late joiners receive the remaining duration. Movement retains the project's existing owner-authoritative NetworkTransform model; this change does not introduce prediction/reconciliation.

Optional development launch arguments `--mecha-local-client --mecha-character zero` use the normal selection/confirm/connect flow without a person clicking the development player. Without the character argument, the selection screen remains interactive. Online `--mecha-join-lobby` also waits for selection; it does not join while the modal is unanswered.
