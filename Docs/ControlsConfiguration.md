# Controls configuration

Configuration > Controls has Controller and Keyboard tabs. The Keyboard tab includes mouse buttons. Every gameplay, system shortcut, and supported menu-navigation binding has a row with a shared localized action name, a description, its current input, Clear and Reset. Existing alternate bindings remain separate editable slots. Native pointer position/scroll, touch, XR and joystick tracking are outside these two device tabs.

Select the binding to listen for a replacement. Keyboard capture accepts keyboard keys and mouse buttons; Escape or the Cancel button cancels. Controller capture accepts controller buttons, triggers and compatible sticks/D-pad controls. Tap to assign; hold the current Back binding to cancel. Capture also cancels after ten seconds or loss of the active controller. The previous binding survives cancellation and conflicts. Reset restores one binding; Restore Tab Defaults restores only that device group. Essential menu access, navigation directions, confirm and back retain a usable binding.

`ControlBindingSettings` is the authored catalog at `Assets/_Project/Settings/Interface/ControlBindings.asset`. It owns action identifiers, localized names/descriptions, tutorial inclusion and capture duration. `GameControlBindings` owns a runtime clone; native binding overrides persist under `Mecha.Controls.Overrides` in the shared JSON [save system](SaveSystem.md). The original PlayerPrefs key is imported once. Registered gameplay and interface action copies receive overrides at startup and after changes. The source Input Action asset and shared profiles remain unchanged during gameplay. UI Cancel is mirrored to the system Back shortcut; when Menu already uses the same input, only Menu handles that event.

The installed Input System supplies interactive rebinding, composite bindings, native control compatibility, display paths and JSON persistence. uGUI Button/ScrollRect/Mask, explicit Selectable links, the existing UiSelectionScroll and UiInteractionFeedback supply interaction, scrolling and persistent focus. The custom code fills the concrete project gap: there was no binding persistence, action-description catalog, conflict policy or remapping settings flow. No new package or artwork was needed.

Tutorials and navigation hints compose current bindings, shared action titles, and localized templates. Skill names reuse Combat entries; navigation labels and repeated scene/prefab labels share canonical entries. `LocalizationConsolidation.csv` records 181 retired entry mappings. `LocalizationDuplicateReview.csv` records the remaining intentional equal values, including controller button identities, printable keyboard characters, ready commands versus states, and directional notation. Automatic capture now reuses an existing equal static label in the same category; explicit runtime lookup keys remain explicit contracts. English remains the only locale.

The older controller-help and keyboard-tutorial fields are retained for compatibility with historical authoring tools; the live tutorial reads the shared controls catalog. Edit current wording in Unity Localization tables and the controls catalog.
