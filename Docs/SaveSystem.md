# Local JSON saves

Player settings now live in `Settings.json` inside Unity's `Application.persistentDataPath`. On the current Windows machine the file is `C:/Users/Elian/AppData/LocalLow/DefaultCompany/project-mecha/Settings.json`. Unity resolves the location on each platform; no account name or absolute machine path is embedded in runtime source. The Editor and a desktop build with the same company/product identity share this file.

`GameSave` owns file loading, typed values, JSON payloads and commits. `GameSaveKeys` owns project setting paths. Use `Mecha.Category.Name` with PascalCase words: `Mecha.Audio.Master`, `Mecha.Audio.Ui`, `Mecha.Audio.Sfx`, `Mecha.Video.Vsync`, `Mecha.Video.FrameLimit`, and `Mecha.Controls.Overrides`. The API validates the naming convention. The dot paths become nested JSON objects. Native Input System binding payloads retain their package-defined lowercase properties such as `bindings` and `path`; they are stored as JSON objects, not escaped strings.

The root `Version` currently equals 1. The installed official `com.unity.nuget.newtonsoft-json@3.2.2` package supplies JSON parsing and typed tokens. Unity's built-in JsonUtility cannot represent the extensible property tree or embedded package payload without an additional string format, so this uses the existing package rather than implementing a serializer or adding a dependency.

Getters return caller-provided defaults for missing or wrongly typed values. Setters stage changes in memory; call `GameSave.Save()` to commit a group. Controls save after a change, audio saves when leaving the screen and on pause/shutdown, and video saves only applied/confirmed values. Pending video drafts and rejected display changes remain unsaved. Quit also flushes pending values. Components keep runtime state and profiles remain read-only.

Each commit writes and flushes `Settings.json.tmp`, then atomically replaces the primary file. `Settings.json.bak` retains the previous valid primary. Loading malformed JSON preserves the primary as `Settings.json.Corrupt.<UTC timestamp>` and attempts backup recovery. If neither primary nor backup exists, defaults and migrated preferences initialize the file. Unreadable files, an invalid backup, or a newer format block writes instead of overwriting existing data. A failed commit keeps pending changes for retry, exposes `GameSave.LastError` and logs the failure; Controls and Video show a localized save-failure message.

`LegacySettingsMigration` imports existing audio/video PlayerPrefs and the original `mecha.controls.overrides.v1` remap JSON once. It maps legacy `UI`, `SFX`, and `VSync` names to `Ui`, `Sfx`, and `Vsync`. Existing JSON values take precedence. The JSON marker `Mecha.Migration.PlayerPrefs` prevents subsequent registry imports. Legacy preferences are retained for rollback and are no longer written by game settings. General's sole approved English locale remains owned by Unity Localization.

Manual validation on 2026-10-18 confirmed import of the existing audio/video values and the user's secondary-fire V remap. Changes made through the Audio, Controls and Video screens produced a valid JSON file and backup. A new Play session reloaded the adjusted master volume, G jump binding, unchanged V secondary-fire binding, and confirmed Vsync selection. Compilation and runtime console checks passed. The user's original settings were restored in both the primary file and backup, and MainScene was restored with Play Mode stopped. Backup recovery and I/O failure branches were reviewed statically. No automated tests or network sessions were created or run.

`GameSave`, `GameSaveKeys`, and `LegacySettingsMigration` are provisional Code. Documentation and manual inspection tooling are Others. The JSON files are device-local runtime output outside the repository; they are not authored configuration assets or version-controlled content.

General highlight preferences use Mecha.General.SelfHighlight (false by default) and Mecha.General.PlayersHighlight (true). A choice persists immediately through GameSave; runtime presentation caches the loaded choices until changed. Each controls name and ground ring together. English locale selection remains with Unity Localization.
