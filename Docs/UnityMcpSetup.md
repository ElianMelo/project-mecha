# Official Unity MCP setup

Migrated on 2026-10-14 at the user's request. This change affects Editor tooling; the gameplay implementation remains intact.

## Installed integration

- Unity Editor: 6000.3.11f1.
- Official Unity CLI: 1.0.0-beta.13.
- Official UPM package: `com.unity.pipeline@0.8.0-exp.1`, resolved from Unity's package registry.
- MCP transport: the CLI's built-in `unity mcp` stdio server. It discovers the project's authenticated local Pipeline endpoint; no cloud MCP session is required.
- Codex registration: `.codex/config.toml`, generated by Unity's CLI and pinned to this project's absolute path. The generated network configuration permits the local Editor connection.
- Official project skills: `.agents/skills/unity-cli` and `.agents/skills/unity-pipeline`.

Unity describes this as the replacement for its older in-Editor MCP server: [official CLI and Pipeline guide](https://unity.com/resources/a-beginners-guide-to-unity-cli-and-the-pipeline-package). The installed package also provides its [official manual](https://docs.unity3d.com/Packages/com.unity.pipeline@0.8/manual/index.html).

## Process

1. Installed Pipeline with `unity pipeline install --project-path <project>`; allowed Unity to import and compile it.
2. Discovered the official live commands, inspected the current Editor state, and verified a read-only C# evaluation.
3. Removed `com.ivanmurzak.unity.mcp@0.93.4` with the official `package_remove` command. Verified its asynchronous completion.
4. Removed the now-unused OpenUPM scoped registry through Unity's Package Manager API; its only scopes served the removed package and dependency. The old `extensions.unity.playerprefsex` dependency is no longer resolved.
5. Verified the legacy NuGet installation ledger owned all 42 DLLs in `Assets/Plugins/NuGet`, and checked for project source references before deleting that folder through `AssetDatabase`. Removed its `UNITY_MCP_READY` and `UNITY_MCP_DEPS_8` symbols from all affected build targets, including the separate dedicated-server target.
6. Removed 77 generated legacy skill folders, the project-local old connection settings, and the stopped cached legacy server. Recoverable copies of the legacy DLLs and generated skills are in ignored `Logs/LegacyMcp-2026-10-14/`; no connection credentials were included.
7. Registered the official server with `unity mcp configure codex --local --project-path <project> --yes` and installed its matching skills with `unity skill install codex --local --yes`.
